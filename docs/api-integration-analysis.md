# 外部 API 与数据功能反推

本轮结论：已观察到 ERP 自有后端按业务域提供数据接口；外部平台API、插件采集与内部加工可能在后端汇合，但连接器、供应商和同步机制尚未证实。用户关于第三方API接入的说明作为调查前提，不冒充网络观测证据。

## 已观察的边界

所有下表请求的可见目标都是 `https://erp.yeeke.com`；路径省略 `/erp-boot` 前缀。完整脱敏目录见 [api-observations.json](../research/api-observations.json)。请求正文、响应正文、字段schema和业务错误码均未采集。

| 页面/证据 | 可见接口示例 | 能支持的结论 | 不能支持的结论 |
|---|---|---|---|
| 采集配置 E11 | GET `/collection/common/config/queryByUser`、`/collection/shop-template-binding/list`、`/ai/sourcing-pricing/config` | 采集配置、店铺模板绑定和AI核价配置有独立读取入口 | 核价究竟调用哪个供应商、是否实时核价 |
| 店铺授权 E12 | GET `/shop/info/list`、`/shop/info/group/list`、`/shop/info/auth/platform/statistics` | 店铺连接信息、分组和授权概览可单独读取 | OAuth流程、权限scope、Token保存位置及续期机制 |
| 选品库 E13 | GET `/pipeline/collection/list`、`/pipeline/collection/claim/count` | 选品库列表和认领计数分开查询 | 采集是否全部来自平台API，或一件商品能否认领多店 |
| 上架任务 E14 | GET `/pipeline/workflow/list`、`/pipeline/workflow/statistics`、`/pipeline/collection/shops`、`/pipeline/collection/sites` | 任务列表、统计和店铺/站点选项有分界 | 真正任务队列技术、执行节点、重试顺序、发布回执 |
| 订单 E15 | POST `/orders/queryOrderList`；GET `/orders/platformStatusEnums`、`/orders/statistics/statusCount` | 列表查询、平台状态枚举和队列计数分开 | 列表来源是实时平台API还是内部快照，是否使用Webhook |
| 店铺统计 E16 | GET `/sales/store-stats/filter-opts`；POST `/sales/store-stats/page`、`/sales/store-stats/list` | 报表具有独立查询入口 | 数据一定来自账单、实时订单或独立数仓 |
| Shopee商品 E17 | POST `/erp/optimize/online-product/list`、`/statistics`、`/item-status/counts`；GET `/batch-edit/progress` | 商品列表、平台状态计数、优化统计和批量编辑进度可单独查询 | 接口仅支持Shopee、进度采用固定轮询、API与平台官方字段一一对应 |

同源前缀不等于单体部署；路径分域也不证明存在对应微服务或数据库表。上述接口都是浏览器到ERP的接口，不能当作平台官方API文档，也不应直接用于外部接入开发。

## 数据来源预测与职责划分

以下均为 inferred 的设计建议；供应商名称和真实映射为 unverified。

| 数据族 | 候选来源与生产方 | ERP需承担的职责 | 下游消费方 | 当前依据 |
|---|---|---|---|---|
| 货源标题、图片、规格、报价 | 插件、导入、货源API或聚合服务 | 来源标识、抓取时间、去重、字段归一化、核对 | 选品库、认领工作流 | E02、E03、E11、E13 |
| 店铺、站点、连接状态 | 外部商家授权接口及ERP配置 | 店铺身份映射、授权状态、租户隔离、能力检查 | 商品、订单、报表 | E10、E12、E14 |
| 在线商品、库存、平台状态 | 平台商品API或同步导入 | 平台快照、外部ID映射、平台状态与优化任务分离 | 诊断优化、重新发布 | E05、E17 |
| 订单、金额、物流状态 | 平台订单API/回调或导入 | 去重、状态映射、事件时序、履约编排 | 待办、采购/发货、统计 | E06、E15 |
| AI文案、图像、核价结果 | 内部算法或外部AI/货源服务 | 任务状态、输入版本、结果关联、失败处理 | 工作流与素材库 | E07、E11 |
| 销售指标 | ERP订单汇总、账单或组合口径 | 时间窗口、币种、取消/退款规则、同步水位 | 工作台和报表 | E01、E08、E09、E16 |

插件入口已观察，但插件自身流量没有采集；不能把货源采集统一解释为API抓取。反之，页面不直接请求外部平台，也不能排除后端调用平台API。

## 建议的数据接入架构

概念数据流：外部平台/货源连接器 → 接入校验与身份映射 → 标准化业务快照 → 工作流/订单域 → 统计投影。浏览器只访问ERP的查询/任务接口。发布、发货等命令由连接器向外部平台执行并保留回执。这是可实现的框架建议，不是对原站拓扑的确认。

连接器建议按能力拆分：店铺连接、商品读取、订单读取、履约命令、刊登命令、货源解析、AI加工。每个平台声明支持的能力、站点和字段，不以相似页面推断功能相同。核心域使用业务语义，平台枚举与字段转换留在适配层。

建议保存的溯源元数据（均为自建设计名，非已发现JSON键）：来源系统、外部对象引用、租户/店铺引用、源更新时间、抓取时间、映射版本、同步批次、游标/水位和内部对象版本。原始载荷若未来确需保存，应放受控存储，不进入本公开仓库。

## 同步、冲突和一致性预测

| 关注点 | 建议方案 | 原站当前证据状态 |
|---|---|---|
| 初次与增量同步 | 首次分页拉取；增量按更新时间/游标推进，成功落库后提交水位；保留重叠窗口去重 | 未验证分页字段与游标语义 |
| 平台回调 | 若平台支持回调，接入幂等事件收件箱，并用定期对账补漏 | 未观察后端Webhook，不能认定已部署 |
| 限流与授权失效 | 按平台/店铺控制并发；尊重服务端重试信号；授权错误进入等待续权 | 未触发限流或失效实验 |
| 重复和乱序 | 以平台、店铺、外部对象形成身份键；按源版本/时间判断过期事件 | 未验证真实主键、版本号和时间可靠性 |
| 发布结果不明 | 区分请求已提交、平台受理、结果确认；先对账后重试 | 没有执行发布或读取回执 |
| 人工编辑与同步冲突 | 草稿/优化版本和平台快照分离；以版本检查保护人工改动 | E05状态分维度支持该建议，但存储方案未知 |
| 统计滞后 | 展示截至时间、业务窗口、口径版本；对账后重算受影响窗口 | UI有统计时间；ETL、时区、汇率及退款规则未知 |

不要将一个列表HTTP200等同于外部平台同步成功，也不要把批量进度接口等同于任务已发布到平台。

## 可继续验证的问题

假设与反证条件见 [hypotheses.json](../research/hypotheses.json)。优先做不触发业务变更的差分观察：仅切换已有状态/平台筛选，比较端点是否变化；查看已有任务的只读详情，寻找节点/回执字段；查看已有同步记录的时间与错误类型。

要确认平台实际接入方式，需要隔离环境中的授权资料、受控后端调用日志或官方连接配置；要验证重试、回调及去重，则需要模拟数据和明确测试条件。商业转化、收费、推广和广告预算流程仍排除。
