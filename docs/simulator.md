# 本地 ERP 模拟器

版本0.3.0，Node.js 22+，零第三方依赖；不访问原站、第三方API或真实业务数据。浏览器会话与Cookie不参与模拟。

```powershell
npm run simulator
```

打开 http://127.0.0.1:4173 。可用 `ERP_SIM_PORT` 修改端口。交互数据仅保存在内存，进程重启即重置；原站没有被修改。

```powershell
npm run simulate          # 执行9项实验，不覆盖证据
npm run simulate:record   # 明确重新生成研究结果，随后审查差异
npm test                 # 自动化、HTTP及证据一致性检查
npm run check
```

## 实现边界与操作

engine.mjs实现虚构平台适配器、按租户/店铺隔离的商品草稿、审核版本、认领任务、故障注入、订单收件箱、同步游标、事件发件箱和统计投影。scenarios.mjs以明确业务断言验证设计，run.mjs输出可重复的结果。

初始交互任务处于READY_TO_PUBLISH；点击“注入已受理超时”，任务进入RECONCILE_REQUIRED，再点击“推进任务 / 查询回执”确认完成，平台商品数与提交次数均应为1。“注入未知超时”后没有回执，继续推进仍保持待对账，避免盲目重发。

限流后可增加模拟时间再推进；授权失效进入WAITING_AUTH，恢复授权后继续。暂停保留恢复位置。订单事件与统计投影分开：先执行投影得到CNY 10.00，再接收取消并执行投影，变为0.00。9项完整实验可在页面重新运行。

页面仅加载本地脚本和样式，服务只绑定127.0.0.1；命令接口拒绝非本地Origin、非JSON及超大请求。它不是生产级认证或多用户服务，不应暴露到公网。

## 与原站观察接口的关系

模拟服务提供以下6个同名查询入口，均返回 `contract: synthetic-not-site-schema`。路径和HTTP方法来自原站观察，返回体是自建模型，不兼容原站未采集的参数和响应schema；过滤、分页、鉴权协议也未复刻。

| 方法 | 路径（前缀 /erp-boot） | 模拟对象 |
|---|---|---|
| GET | /pipeline/collection/list | 商品草稿 |
| GET | /pipeline/workflow/list | 刊登任务 |
| GET | /pipeline/workflow/statistics | 任务状态计数 |
| GET | /shop/info/list | 虚构店铺连接 |
| POST | /orders/queryOrderList | 订单快照，只读查询 |
| POST | /sales/store-stats/page | 统计投影，只读查询 |

交互命令使用另设的 `/api/command`，它不是对原站写接口的推断。其余观察到的路径未实现时返回404，不伪造完整覆盖。

## 实验覆盖

| 实验 | 核心断言 | 对应证据/假设 |
|---|---|---|
| S01 | 仅采集不排队、审核门槛、分店认领、暂停恢复 | E03/E04/E10/E14；H02/H03 |
| S02 | 编辑使审核失效、旧输入版本不能发布 | E03/E05；H03 |
| S03 | 平台已受理超时，经快照恢复后对账，仅一个商品 | E04/E14/E17；H03 |
| S04 | 限流等待和授权等待有独立恢复条件 | E04/E12/E14；H03/H07 |
| S05 | 重复和过期事件不能回退取消状态 | E06/E15；H01/H05 |
| S06 | 本地批次失败时订单/收件箱/发件箱/游标一起回滚 | E15；H05 |
| S07 | 投影可滞后和重放，取消撤销有效金额，多币种分开 | E08/E09/E16；H04 |
| S08 | 相同外部ID按租户和店铺隔离，检查能力 | E12/E15/E17；H01/H07 |
| S09 | 同键异值冲突被拒绝，未知发布结果不盲重发 | E14/E15；H03/H05 |

另以50组确定性乱序投递检验订单最终收敛，HTTP集成测试验证POST查询不会修改模拟状态；浏览器实际点击验证超时对账、商品数量及取消后的金额。

## 结果解释与限制

原站网页证据仍是E01–E17；E18专指本地实验。实验只能证明本实现满足这些自建契约，并提供反例来筛选架构方案。H01–H07的原站实现状态保持open；特别是H05不因模拟了事件收件箱而被认定为原站使用Webhook。

实验简化：用单进程对象快照回滚模拟事务；用JSON快照恢复模拟重启，不包含真实进程崩溃、磁盘提交或数据库隔离；模拟平台保存幂等键且提供回执查询，真实平台是否具备这些能力尚未知。生产中必须按平台实际能力选择幂等/对账策略。

模型只实现“仅采集”分支，不实现自动采集上架配置；加工节点为确定性状态推进，没有AI推理、图片处理或成本核价；没有真实OAuth、Webhook、分页调用或供应商限流协议。订单金额用非负整数最小单位；有效金额规则为排除取消，不含退款、税费、汇率、时区与账单对账。未实现数据库、分布式并发、租约、生产凭据和多平台字段映射。
